# ADR 0005 — 0.2.0 breaking-change batch

**Status:** Accepted
**Date:** 2026-05-29
**Issue:** #167
**Implements gate 1 of:** [ADR 0004](0004-path-to-1.0.md)

---

## Context

[ADR 0004](0004-path-to-1.0.md) sequences `0.1.x → 0.2.0 → 1.0` and makes
"0.2.0 shipped" the first 1.0 gate. The
[0.2.0 inventory](../milestones/semver-0.2.0-breaking-inventory.md) lists five
**candidate** breaking changes; the inventory's policy is that an item becomes
**decided** only via an ADR. This ADR is that decision for the batch.

A single batch ADR is used (rather than five micro-ADRs) because the items are
individually small; per-item detail and migration notes live in the inventory.

## Decision

### In scope for 0.2.0

1. **Remove `openApiFileExists` and `DEFAULT_OPENAPI_RELATIVE` from public
   exports.** Internal path-resolution helpers; consumers use `resolveOpenApiPath`
   or an absolute path. (The functions stay in `src/openapi/`; only the
   re-exports from `src/index.ts` are dropped.)
2. **Rename `Nene2AppDatabase.executor` → `queryExecutor`.** Aligns with the
   internal `DatabaseQueryExecutor` type and disambiguates from `readExecutor`.
3. **Raise the minimum runtime to Node 24 LTS / npm 11.** Node 24 is LTS;
   SQLite is stable (no `--experimental-sqlite`). Update `engines` and drop the
   experimental-SQLite caveats.
4. **`TokenVerifier.verify` returns `Promise<Record<string, unknown>>`** — drop
   the `| Record<...>` sync union. `LocalBearerTokenVerifier` wraps in
   `Promise.resolve`.

### Deferred (not in 0.2.0)

- **`createApp()` synchronous return.** Requires a DI/bootstrap redesign
  (separating DB connect from app construction). It gets its **own design ADR**
  before implementation; out of this batch.

## Execution

- Each item ships as its own PR (`feat!:` / `refactor!:`), accumulating under
  CHANGELOG `[Unreleased]`. **Do not bump `package.json` per item** — it is bumped
  to `0.2.0` only at `npm run release:prepare -- 0.2.0` time, so the doc-integrity
  version check stays valid during accumulation.
- Each item updates the **API surface snapshot** (`vitest -u`) and
  `docs/STABILITY.md` as needed — the change is a reviewed diff by construction.
- Suggested order (low → higher blast radius): (1) export removal → (4)
  `TokenVerifier.verify` → (2) `executor` rename → (3) Node 24 minimum.
- 0.2.0 ships when the batch is complete (it need not wait for the other 1.0
  gates — contract coverage and Experimental emptying continue in parallel).

## Consequences

- **Migration** for consumers is concentrated in one minor; documented in the
  inventory and the CHANGELOG `[0.2.0]` section.
- npm goes `0.1.26 → 0.2.0`; the public surface shrinks by two exports and
  renames one field — all caught by the surface-snapshot guard.
- Closes ADR 0004 gate 1 when shipped.
